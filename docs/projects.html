Multi-Cloud Free-Tier Platform

Work in progress

A single dashboard that provisions compute across AWS, GCP, Azure and Oracle Cloud — strictly inside each provider's free tier — using Terraform, with a unified status view and cost comparison.

  • Next.js → FastAPI → Celery → Terraform, with Postgres holding users, resources and encrypted credentials
  • Every request is checked against a hardcoded free-tier allowlist server-side before Terraform runs, and mirrored again as Terraform variable validation — rejected at both layers
  • Per-tenant Terraform workspaces, so one user's state never touches another's
  • An hourly auto-destroy sweep tears down anything past its 24-hour safety window, so nothing is left orphaned
  • Credentials encrypted at rest with Fernet, never committed
Two independent rejection points for out-of-tier requests; state isolated per tenant; unused resources reaped hourly.

Simple-Actions

Reference

A library of GitHub Actions workflow templates for building, signing, packaging and cleaning up release artifacts across Windows and Linux runners.

  • Composite pipeline: build on a Windows runner (NuGet restore, MSBuild, installer) → sign on a self-hosted runner → publish a GitHub release → purge artifacts
  • Code signing isolated to a self-hosted runner so keys never touch a shared runner
  • Separate workflows for dpkg packaging of a C++ app and for keeping git submodule refs current
  • Batch helpers for the signing and artifact-move steps

Matter Test Harness Image Builder

Active

Bash automation that provisions a Raspberry Pi running Ubuntu 22.04 into a complete Matter (CHIP) Test Harness — then produces a compressed, distributable SD-card image of the finished environment.

  • Installs Docker, Poetry and system dependencies, then clones and builds the chip-certification-tool harness
  • Handles network and service configuration, PAA certificate fetching, and sample-app updates
  • Images the live SD card with dcfldd and shrinks it via PiShrink, so a working harness can be cloned to new hardware instead of rebuilt
  • Single orchestrator script runs the whole sequence end to end, reboots included

SpeedTestDD

Complete

Benchmarks the optimal dd block size for a given machine by sweeping sizes from 512 B to 64 MB and reporting throughput for each.

Clears the kernel page cache between runs so results reflect real disk I/O rather than memory. Useful before imaging or cloning drives, where picking the right block size is the difference between minutes and hours.
