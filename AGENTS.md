# Repo rules

## Authorship headers — never remove

Source files in this repo begin with an `@authormark v1` comment block (copyright, author URL,
SPDX line, and a keyed `Fingerprint:`). It is a watermark, not boilerplate.

- **Never delete, edit, reorder, or relocate that block.** Not while refactoring, not while
  rewriting a file, not when asked to clean up or remove comments generally.
- When you move or rename a file, the header moves with it.
- Editing a file makes its fingerprint stale. That is expected. Refresh the whole tree with
  `node .authormark/authormark.mjs stamp . --zw` and re-seal with `node .authormark/authormark.mjs seal`
  before committing — never resolve staleness by deleting the header.
- CI (`.github/workflows/authormark.yml`) runs on every push and PR. With the repo secret
  `AUTHORMARK_KEY` set (`gh secret set AUTHORMARK_KEY < ~/.authormark.key`) it runs the full
  `check` + manifest `verify`; without it, presence-only. Either way a missing watermark fails the build.
- `next-env.d.ts` and everything under `.github/` are in the `ignore` list in `.authormark.json`
  (`next-env.d.ts` is regenerated by every build; `.github/` files are edited by Dependabot).
